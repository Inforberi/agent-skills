# Общие правила работы агента

Выполняй запрос простейшим способом, который даёт полный, корректный и поддерживаемый результат.

## Объём и контекст

- Следуй запросу и соглашениям проекта. Перед правками проверь состояние рабочей копии и diff. Сохраняй чужие правки, публичные контракты и данные. Изменение контракта требует согласования.
- Начинай с ближайшего кода, его вызывающих мест и проверок. Используй `rg` и чтение нужных диапазонов. Расширяй поиск по мере необходимости, избегай больших выгрузок логов, lockfile и generated code. Повторно читай файл при изменении или новом вопросе к нему.
- Переиспользуй компоненты, архитектуру, зависимости и возможности платформы. Открывай документацию по относящемуся к задаче API для версии проекта. Добавляй код, зависимости и рефакторинг только при необходимости для результата.
- Учитывай затронутые границы доверия, ошибки, доступность, очистку ресурсов, конкурентность и данные.

## Выполнение

- Локальная правка — найти причину, исправить, выполнить целевую проверку. Обычная фича — кратко определить результат и проверки. Сложная работа — до кода определить границы, критерии и порядок самостоятельных частей.
- Используй команды проекта и прямые инструменты. Скрипт оправдан сложной или повторяемой обработкой. Локальные сервисы, установки и полные прогоны запускай для конкретной задачи и завершай процессы, поднятые для проверки.
- Объединяй независимые чтения, если это безопасно. После сбоя выясни причину и меняй подход по фактам. Повторяй команду после изменения входных данных или подтверждения временного сбоя.
- На большой задаче основной агент координирует работу и отвечает за конечный результат. Если правила проекта и возможности клиента допускают делегирование, поручай объёмный сбор информации и реализацию самостоятельных частей младшим моделям по правилам `deliver-feature`. Разделяй области чтения и правок, назначай одного владельца общего файла и запускай до трёх субагентов одновременно для независимых поручений. Локальные правки выполняй напрямую с целевой проверкой.

## Проверка и завершение

- Подбирай один достаточный набор проверок для всего изменения. Для документации проверь diff и затронутые ссылки или команды. Для изменения поведения проверь затронутый сценарий. Добавляй сборку, статические, браузерные и широкие прогоны, когда они покрывают конкретный риск или требуются проектом.
- Начинай с кода и существующих проверок проекта. Если для приёмки нужно интерактивно управлять браузером или приложением, объясни зачем и дождись разрешения на Computer Use. Прямой запрос пользователя или его заранее заданное разрешение действуют в указанных границах.
- На обычной задаче переиспользуй существующие проверки. Добавляй тест или целевую регрессионную проверку при запросе, требовании проекта или значимом риске, который имеющиеся проверки не покрывают. Для безопасности, прав, платежей, миграций, сохранности данных и конкурентности обязательны соответствующие проверки риска.
- Применяй эту политику совместно с профильными скиллами. В этом проекте она определяет, когда правило Ponytail о тесте для нетривиальной логики требует нового теста. Обязательные проверки по запросу и существенные риски сохраняются.
- Привязывай результаты к проверенному состоянию. Повторяй успешную проверку при относящемся к ней изменении. Остановись после выполнения критериев.
- В итоговом ответе кратко назови результат, фактически выполненные проверки и существенные ограничения или пропуски.
