# Design System

## Подготовь основу до экранов

Начни с согласованного пользовательского сценария и визуального направления. Найди действующую тему, типографику, шкалу отступов, библиотеку компонентов и правила имён. Для существующего продукта укажи, что можно переиспользовать. Для нового продукта создай базу, необходимую первому рабочему сценарию, и добавляй общие элементы по фактической потребности.

Если есть макет, сопоставь его стили, переменные и компоненты с кодом. Выбери один источник редактирования токенов для согласованной области. Для обмена между инструментами используй принятый в проекте формат. [Пример веб-основы](references/web-foundation.md) подходит как ориентир при отсутствии соглашений.

## Раздели ответственность

| Слой | Ответственность |
| --- | --- |
| Глобальная база | Подключение шрифтов, базовые стили документа и применение темы. |
| Токены | Общие значения и шкалы для цвета, типографики, отступов и геометрии. Смысловые имена отражают использование. Тема задаёт значения для `text-default`, `surface` и `action-primary`. Токен компонента нужен, когда его значение должно меняться независимо. |
| Типографика | Роли вроде `heading`, `body` и `label` задают семейство, размер, вес и межстрочный интервал. `Text`, `Heading` или классы проекта применяют эти роли. HTML-элементы соответствуют смыслу и структуре документа. |
| Раскладка | Контейнеры, ряды и сетки отвечают за расстояния между элементами и адаптивность. Используй шкалу отступов и принятые средства раскладки. |
| Компоненты | Внутренние отступы, визуальные варианты, фокус, клавиатурное поведение и применимые состояния. Держи локальные стили у компонента. Меняй внешний вид по токенам, сохраняя семантику. |
| Паттерны и экраны | Собирай повторяемый паттерн из компонентов, а данные и шаги сценария держи на уровне фичи. Передавай содержание и действия через возможности композиции стека. |

Сначала собери один работающий экран на этой основе. Выделяй общие паттерны, когда у них есть повторяющаяся задача и понятные границы. Используй явные варианты для устойчивых различий. Если меняется состав частей, дай экрану возможность собрать их напрямую.

## Проверь изменения системы

Открой первый экран в браузере и проверь обычный и узкий размеры, длинный текст, фокус, контраст и нужные состояния. При добавлении или изменении общего токена проверь его эффект на нескольких затронутых потребителях, если они есть. Если есть поддерживаемые темы, проверь затронутые темы. После проверки верни временные значения. Зафиксируй, где теперь меняется общий стиль и какие исключения нужны по смыслу.
