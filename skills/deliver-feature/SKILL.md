# Deliver Feature

## Подбери маршрут

Следуй запросу, инструкциям проекта и его разрешённым инструментам. Прочитай ближайшие реализации и команды проверки. Для маленькой правки текста или стиля ограничься затронутым сценарием. Для запроса на план передай готовый план и дождись разрешения на реализацию.

| Признак задачи | Что подключить, если доступно |
| --- | --- |
| Реализация по Figma, изображению или приложенному макету | `build-from-design` и `product-ui`. |
| Новый экран или поток без макета | `design-from-brief` и `product-ui`. |
| Новая тема, общие компоненты или новая UI-система | `design-system` для подготовки основы до сборки экранов. |
| Только бизнес-логика или реализация уже определённого решения | `ponytail` и инструкции проекта. |
| Решение зависит от Next.js или SvelteKit | `nextjs` или `sveltekit` для установленной версии и затронутого поведения. |
| Жесты, анимация или особенности мобильного браузера | `apple-design` или `mobile-native` по задаче. |

Используй установленный скилл через механизм текущего агента. При его отсутствии придерживайся этого плана и опирайся на существующие соглашения проекта. Дополнительные зависимости подключай в рамках разрешений проекта.

## Подготовь приёмку до кода

1. Запиши исходный пользовательский путь, результат и границы изменения. Сверь расхождения между макетом, запросом и поведением продукта. Разреши вопросы, которые меняют сценарий, контракт или права. Для новой поверхности без макета используй выбранное с пользователем направление или сделай выбор, если он делегирован.
2. Определи источник данных, реальные действия и применимые состояния. Для UI зафиксируй источник токенов и компонентов. В новом проекте заложи минимальную основу дизайн-системы в первой задаче. Для существующего проекта укажи, что переиспользуется и что действительно нужно добавить.
3. У каждого задания задай наблюдаемое условие и способ проверки. Запланируй первым один путь через обычную точку входа до наблюдаемого результата. Оставь независимо изменяемые части для параллельной работы.

## Реализуй и проверяй по ходу

Основная модель принимает решения и сохраняет один план. Если делегирование разрешено, передай ограниченные задания более экономичным реализаторам, а независимую проверку — лёгкой модели. Используй [шаблоны передачи работы](references/handoff.md). При отсутствии такого режима выполни этапы последовательно.

Проверь первый рабочий сценарий до расширения покрытия. Для UI пройди его в браузере и сверь визуальное решение. Для изменений данных проверь фактическое сохранение и повторное чтение, если это часть приёмки. При расхождении сначала исправь причину, затем повтори затронутую проверку. После объединения частей проверь общие контракты на итоговой версии изменений и сообщи подтверждённые результаты и пропуски.
