# PostgreSQL

- Определи версию сервера, используемые драйвер или ORM, runner миграций и роль приложения. Сохраняй RLS, полномочия и принятый способ миграций. Передавай данные параметрами, а динамические идентификаторы выбирай из допустимых значений через безопасный API драйвера.
- Сначала определи инвариант данных. Для одной атомарной операции предпочитай условное обновление или существующее ограничение. Для связанной серии операций используй одну транзакцию и её соединение. При конкурентных изменениях проверь уровень изоляции, порядок блокировок и специфику повторов. При ошибке сериализации повторяй всю транзакцию только там, где повтор безопасен. Сверяй [документацию PostgreSQL для версии проекта](https://www.postgresql.org/docs/) по изоляции и явным блокировкам.
- Для миграции оцени блокировки, размер и состояние данных, совместимость со старой версией приложения при поэтапном выкатывании и путь восстановления. Проверь, оборачивает ли runner шаги в транзакцию. `CREATE INDEX CONCURRENTLY` выполняется вне блока транзакции, а после ошибки может остаться невалидный индекс.
- Проверяй инварианты, конкуренцию или права на тестовом PostgreSQL с нужной ролью, если они затронуты. Миграцию проверь от предыдущей схемы на репрезентативных данных вместе с предусмотренным восстановлением. Для изменения производительности сравни планы на сопоставимых данных. `EXPLAIN ANALYZE` исполняет оператор, поэтому изменяющие запросы измеряй в изолированной БД.
