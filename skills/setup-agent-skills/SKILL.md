# Настройка Agent Skills

Запуск через `skills use --agent` — просьба сразу настроить открытый проект. Начни с его контекста.

1. Работай в корне целевого проекта. Прочитай действующие инструкции и ближайшие признаки стека, например зависимости в `package.json`, `go.mod`, подключение БД или каталог миграций. Учитывай уже известные цели пользователя. Если проект пуст, стек неясен или в монорепозитории есть несколько целей, уточни только то, что меняет выбор. Можно задать несколько вопросов. Если стек пока открыт и пользователь хочет начать, достаточно базовых скиллов.
2. Подбери отсутствующие скиллы в объёме запроса. Если пользователь перечислил конкретные скиллы, придерживайся списка. При общей настройке подключи `setup-agent-skills`, `ponytail`, `deliver-feature` и профили для подтверждённого стека или текущей цели. Установи постоянную копию `setup-agent-skills`, если он доступен только из ссылки или временного запуска через `skills use`. В ходе задачи по правилу проекта подключай только отсутствующие профили, которые нужны сейчас. Переиспользуй доступные версии, включая уже подключённый Ponytail.

   | Контекст | Скилл |
   | --- | --- |
   | Next.js или SvelteKit | `nextjs` или `sveltekit` соответственно |
   | Go API или горутины | `go-backend` |
   | Схема, запросы, транзакции или миграции PostgreSQL | `postgresql` |
   | Экран по Figma, скриншоту или визуальной спецификации | `build-from-design` |
   | Проектирование экрана без макета | `design-from-brief` |
   | Общие токены или компоненты | `design-system` |
   | Интерфейсные действия, тексты и состояния | `product-ui` |

3. При общей настройке или установке определи ревизию. Используй строку `Ревизия Inforberi/agent-skills: <полный SHA>` в действующих инструкциях проекта. При первичной настройке разреши явно выбранную пользователем ревизию в SHA коммита или возьми SHA из `git ls-remote --exit-code https://github.com/Inforberi/agent-skills.git refs/heads/main`. Проверь, что получен один полный 40-символьный SHA, и сохрани его до установки, чтобы повтор после сбоя использовал тот же источник. Если проектный файл ещё отсутствует, создай штатный файл клиента в корне, например `AGENTS.md` для Codex или `CLAUDE.md`. Сохрани остальные инструкции. При несовпадающих записях или недоступной ревизии сообщи причину.

   Новая запись определяет источник будущих установок. Если в проекте уже есть копии набора с другой или неизвестной ревизией, используй их как ранее доступные и сообщи об этом при настройке. При явно запрошенном обновлении разреши целевую ревизию в SHA. Для обновления до текущей версии получи SHA ветки `main` той же командой. Включи в установку все ранее подключённые копии набора для текущего клиента. Сохрани новый SHA после проверки всех обновлённых копий. При частичном сбое сообщи целевой SHA и какие профили осталось обновить.

4. В корне проекта установи выбранные скиллы для текущего агента. При пустом списке выбранных скиллов пропусти команду. Для CLI нужен Node.js 22.20 или новее. Подставь SHA закреплённой или явно запрошенной новой ревизии вместо `REVISION` и нужные имена после `--skill`. Пример для Codex при доустановке профиля Next.js:

   ```sh
   npx --yes skills@1.7.4 add 'https://github.com/Inforberi/agent-skills.git#REVISION' --agent codex --skill nextjs --yes
   ```

   Для Claude Code укажи `claude-code`. Для других клиентов используй их идентификатор в CLI. Если Node.js недоступен, используй штатный установщик клиента или скопируй нужные папки скиллов целиком из снимка этой ревизии. При явно выбранном локальном источнике используй путь к чистому снимку зафиксированного коммита. Тестовые копии можно устанавливать из рабочей папки по явному запросу для проверки. При ограничении записи используй штатный запрос разрешения. Если установка остаётся недоступна, сообщи причину и дай команду с сохранённой ревизией.

5. Проверь каждый выбранный скилл по списку клиента или файлам. После сбоя установи только отсутствующие или неполные скиллы из той же ревизии. При общей настройке или явном обновлении набора сохрани правила ниже, когда помощник доступен в следующих чатах. Если блок уже есть, добавь только отсутствующее правило. Сохрани ограничения пользователя и проекта на делегирование.

   ```markdown
   ## Скиллы по мере работы

   Выбирай скиллы по текущей задаче. Если необходимый профиль из Inforberi/agent-skills ещё недоступен, используй `setup-agent-skills`, чтобы установить только этот профиль локально, затем продолжи задачу. Правило относится к скиллам из Inforberi/agent-skills.

   Для изменений поведения и задач из нескольких связанных шагов используй доступный `deliver-feature`, даже если в запросе скилл не указан. Применяй его правило автоматического делегирования, когда клиент поддерживает выбор модели субагента и правила среды и проекта допускают такой запуск.
   ```

6. При подключении в ходе задачи прочитай установленный `SKILL.md` и продолжи работу в текущем чате, даже если список скиллов ещё не обновился. По итогам общей настройки кратко назови подключённые скиллы, ревизию и файл с правилом.
