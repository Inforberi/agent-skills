# Настройка Agent Skills

Запуск через `skills use --agent` — просьба сразу настроить открытый проект. Начни с его контекста.

1. Работай в корне целевого проекта. Прочитай действующие инструкции и ближайшие признаки стека, например зависимости в `package.json`, `go.mod`, подключение БД или каталог миграций. Учитывай уже известные цели пользователя. Если проект пуст, стек неясен или в монорепозитории есть несколько целей, уточни только то, что меняет выбор. Можно задать несколько вопросов. Если стек пока открыт и пользователь хочет начать, достаточно базовых скиллов.

   При общей настройке или обновлении найди существующие команды локальной проверки. Начни с инструкций проекта, затем посмотри скрипты нужного пакета или задачи в `Makefile`, `Taskfile.yml` и аналогичных файлах. Если команды там нет, проверь конфигурацию тестов и CI. Для монорепозитория уточни рабочий каталог и область каждой найденной команды. Сверь, что команда определена и предназначена для локальной проверки. На этом шаге достаточно прочитать конфигурацию.

2. Подбери отсутствующие скиллы в объёме запроса. Если пользователь перечислил конкретные скиллы, придерживайся списка. При общей настройке подключи `setup-agent-skills`, `ponytail`, `deliver-feature` и профили для подтверждённого стека или текущей цели. Установи постоянную копию `setup-agent-skills`, если он доступен только из ссылки или временного запуска через `skills use`. В ходе задачи по правилу проекта подключай только отсутствующие профили, которые нужны сейчас. Переиспользуй доступные версии, включая уже подключённый Ponytail.

   Graphify — сторонняя опция для крупных репозиториев. Подключай её только по отдельному запросу пользователя. [Документация Graphify](https://github.com/Graphify-Labs/graphify#install)

   | Контекст | Скилл |
   | --- | --- |
   | Next.js или SvelteKit | `nextjs` или `sveltekit` соответственно |
   | Go API или горутины | `go-backend` |
   | Схема, запросы, транзакции или миграции PostgreSQL | `postgresql` |
   | Экран по Figma, скриншоту или визуальной спецификации | `build-from-design` |
   | Проектирование экрана без макета | `design-from-brief` |
   | Общие токены или компоненты | `design-system` |
   | Интерфейсные действия, тексты и состояния | `product-ui` |

3. При общей настройке или установке определи ревизию. Ищи строку `Ревизия Inforberi/agent-skills: <полный SHA>` в действующих инструкциях проекта и корневых `AGENTS.md` и `CLAUDE.md`, включая установки для другого клиента. При первичной настройке разреши явно выбранную пользователем ревизию в SHA коммита или возьми SHA из `git ls-remote --exit-code https://github.com/Inforberi/agent-skills.git refs/heads/main`. Проверь, что получен один полный 40-символьный SHA, и сохрани его до установки, чтобы повтор после сбоя использовал тот же источник. Для Codex и Claude Code сохраняй общую запись в корневом `AGENTS.md`. Если запись уже есть в `CLAUDE.md`, перенеси её в `AGENTS.md` при установке общего блока. Для других клиентов используй их штатный файл инструкций. Сохрани остальные инструкции. При несовпадающих записях или недоступной ревизии сообщи причину.

   Новая запись определяет источник будущих установок. Если в проекте уже есть копии набора с другой или неизвестной ревизией, используй их как ранее доступные и сообщи об этом при настройке. При явно запрошенном обновлении разреши целевую ревизию в SHA. Для обновления до текущей версии получи SHA ветки `main` той же командой. Включи в установку все ранее подключённые копии набора для текущего клиента. Сохрани новый SHA после проверки обновлённых копий и блока правил. Если обнаружены копии набора для другого клиента, укажи, что их обновляют отдельно в этом клиенте. При частичном сбое сообщи целевой SHA и какие профили осталось обновить.

4. В корне проекта установи выбранные скиллы для текущего агента. При пустом списке выбранных скиллов пропусти команду. Для CLI нужен Node.js 22.20 или новее. Подставь SHA закреплённой или явно запрошенной новой ревизии вместо `REVISION` и нужные имена после `--skill`. Пример для Codex при доустановке профиля Next.js:

   ```sh
   npx --yes skills@1.7.4 add 'https://github.com/Inforberi/agent-skills.git#REVISION' --agent codex --skill nextjs --yes
   ```

   Для Claude Code укажи `claude-code`. Для других клиентов используй их идентификатор в CLI. Если Node.js недоступен, используй штатный установщик клиента или скопируй нужные папки скиллов целиком из снимка этой ревизии. При явно выбранном локальном источнике используй путь к чистому снимку зафиксированного коммита. Тестовые копии можно устанавливать из рабочей папки по явному запросу для проверки. При ограничении записи используй штатный запрос разрешения. Если установка остаётся недоступна, сообщи причину и дай команду с сохранённой ревизией.

5. Проверь каждый выбранный скилл по списку клиента или файлам. После сбоя установи только отсутствующие или неполные скиллы из той же ревизии. При общей настройке или явном обновлении примени [полный шаблон правил](references/project-rules.md) из целевой ревизии. При запуске из ссылки или старой установки возьми файлы шаблона и скрипта из установленной копии `setup-agent-skills` целевой ревизии или из снимка этого коммита.

   Для Codex и Claude Code запусти [скрипт установки правил](scripts/install-project-rules.mjs) из корня целевого проекта. Подставь фактический путь к скрипту.

   ```sh
   node "/path/to/setup-agent-skills/scripts/install-project-rules.mjs" --claude-import
   ```

   Флаг `--claude-import` добавляет `@AGENTS.md` в `CLAUDE.md` с сохранением существующих инструкций. Пропусти флаг, если Claude Code уже настроен на прямую загрузку `AGENTS.md`. Если Node.js недоступен или используется другой клиент, перенеси шаблон целиком в файл инструкций между строками `<!-- Inforberi/agent-skills:start -->` и `<!-- Inforberi/agent-skills:end -->`. При обновлении замени блок между этими маркерами и сверь с шаблоном. Для Claude Code при необходимости добавь импорт вручную.

   Запиши найденную команду проверки и рабочий каталог вне блока, если их ещё нет в действующих инструкциях. Старый раздел `Скиллы по мере работы` мог содержать правки пользователя: сохраняй их. Если `AGENTS.override.md` в области задачи, настройки клиента или другие действующие инструкции мешают загрузке блока или запрещают делегирование, укажи конкретную причину в итогах. Для повторной проверки загрузки открой новый сеанс клиента.

6. При подключении в ходе задачи прочитай установленный `SKILL.md` и продолжи работу в текущем чате, даже если список скиллов ещё не обновился. По итогам общей настройки кратко назови подключённые скиллы, ревизию и файл с правилом.
