# Интерфейсные тексты

## Пройди по экрану в порядке чтения

1. Определи работу каждой строки. Заголовок называет экран, подпись обозначает поле, кнопка описывает действие, сообщение объясняет результат или следующий шаг. Удали строку, если без неё человек так же хорошо понимает экран и может выполнить действие.
2. Пиши на языке пользователя и продукта. Используй одно название для одной сущности во всём сценарии. Сохраняй голос продукта и термины, которые команда уже использует.
3. Сверяй утверждения с требованиями, данными или фактическим поведением. Это касается прав доступа, сроков, сумм, сравнений, формата выгрузки и эффекта кнопки. Не заполняй пробелы выдуманными фактами, цифрами, отзывами и обещаниями.
4. Показывай важное там, где оно нужно для решения. Рядом с полем поясни нестандартное требование, рядом с ролью опиши её полномочия, до подтверждения назови последствия действия. Сохраняй понятные подписи полей после ввода значения и доступные имена кнопок с иконками.

## Примеры редактуры

| Исходный текст | Решение в интерфейсе |
| --- | --- |
| «Отчёты, которые работают» | «Отчёты» в навигации. «Продажи по дням» на экране соответствующего отчёта. |
| «Все важные показатели в одном месте» под заголовком отчёта | Убери строку. Подпиши сами показатели и укажи период, если без него цифры двусмысленны. |
| «Получайте ценные инсайты» | Убери фразу. Если сравнение уже рассчитано и существенно, покажи факт, например «Заказов на 12% больше, чем в сентябре». |
| «Введите адрес электронной почты» под полем «Email» | Оставь подпись «Email». Уточни формат или допустимый домен только при реальном ограничении. |
| «Продолжить» при отправке приглашения | «Отправить приглашение». «Далее» подходит для перехода на следующий шаг. |
| «Готово! Вы на шаг ближе к эффективной совместной работе» | «Приглашение отправлено», когда отправка подтверждена. Статус «Ожидает ответа» в списке помогает следить за приглашением. |
| «Что-то пошло не так» при повторном приглашении | «На этот адрес уже отправлено приглашение» рядом с полем, если продукт установил эту причину. |

## Состояния и ошибки

- Различай пустой список, отсутствие результатов по фильтру и сбой загрузки. Для нового списка предложи действие, для пустого поиска — изменить запрос или сбросить фильтр, при сбое — повторить загрузку, если это возможно.
- Сообщай причину ошибки, когда она известна и полезна человеку. Если причина неизвестна, назови действие, которое не удалось выполнить, и доступный следующий шаг. При неопределённом результате предложи проверить состояние перед повтором, если повтор может создать дубль.
- Показывай успех после подтверждения. Выбери место, где результат заметят. Если обновлённое состояние и так видно сразу, отдельное уведомление может дублировать его.

На лендинге конкретный заголовок может объяснять аудиторию и пользу. «Онлайн-запись для салонов с напоминаниями клиентам» даёт больше информации, чем «Всё для роста вашего бизнеса», если продукт действительно поддерживает запись и напоминания.
